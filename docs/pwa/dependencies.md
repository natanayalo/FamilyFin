## Ownership model for follow-up PRs

T01 owns only Python API/authentication services and transport contracts. T02 owns the browser API client and every frontend surface, including sign-in/session handling, shell, and design system. T02 can proceed against this document and synthetic fixtures until T01 merges. After the foundation, data modules can proceed independently. One PR should not edit another feature module’s DTOs or financial services without coordinating its owner.

Suggested structure:

- Python adapters: src/family_finance/api/routers/<feature>.py and DTOs in src/family_finance/api/schemas/
- Frontend: frontend/src/features/<feature>/, shared shell/components in frontend/src/components/
- Shared versioned contract: docs/pwa/api-contracts.md and a generated OpenAPI document from the actual adapter once implemented
- Financial logic stays in its present domain modules; route handlers call the exact services listed in the parity matrix.

## Dependency sequence

1. Review this T00 contract; decide user identity bootstrap/recovery, Node deployment mode, host, tailnet name/ACL owners, actor-audit requirement, backup destination/retention, and whether operations controls belong in PWA.
2. Land T01 Python API/auth foundations and T02 frontend shell concurrently. Keep session identity separate from Tailscale identity. T02 uses the documented contracts and synthetic fixtures until T01 is merged. Do not route private data through an external auth or analytics provider.
3. Land independent read-only modules (Overview/Expenses, Data Quality) and then independent write modules (Classification, Planning, Net Worth) once error/Decimal/token contracts are frozen.
4. Land Savings Forecast after Planning and Net Worth; Apartment after Forecast. Ship Automation & Insights read-only status/dry-runs separately from remote mutations; do not expose mutating automation until mandatory per-run verified backup readiness and a successful pre-import backup have been implemented and verified.
5. Run the PWA alongside Streamlit and the CLI using the same database and archives. Compare each service output before the PWA becomes the primary entry point.
6. Verify private tailnet HTTPS, two-user login separation, mobile installability, offline denial of financial views/mutations, mandatory backup readiness for mutating automation, backup verification, and documented manual restore before household rollout. T12 retires Streamlit only after this final parity/recovery gate passes; keep the CLI.

The sequence does not authorize a financial schema rewrite. Existing service logic and financial invariants remain the compatibility target.
