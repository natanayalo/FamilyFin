# Streamlit to PWA parity matrix

Mutation retry safety is conditional: a route may advertise replay safety only after its financial commit and stored response pass the atomic/recovery gate in [api-contracts.md](api-contracts.md). A key alone is not a guarantee. Before that gate, a timeout is outcome-unknown and the client must not automatically retry.

Inventory baseline: current master at b8bb6d069ca9e2202ef90504336baa44918d9dd0, inspected 2026-09-25. There are nine current Streamlit pages in src/family_finance/ui/app.py. All routes and API paths below are proposals, not implemented endpoints. Existing service methods and current UI affordances are distinguished from service-only methods.

Shared shell requirements for every row: Hebrew labels and help text, root lang=he and dir=rtl, usable at 360 px wide and desktop, authenticated API requests, exact Decimal display/input, visible loading/error states, no financial browser persistence, and reconnect required after loss of network. See [api-contracts.md](api-contracts.md) for common transport behavior.

## Inventory completeness and gaps

The nine current Streamlit routes are all mapped above: Overview, Expenses, Data Quality, Classification, Planning, Net Worth, Savings Forecast, Apartment Plan, and Automation & Insights. Every UI action and preview/commit sequence is represented. The full Python service has additional operations that a current page does not expose; those rows are explicitly marked service-only rather than misreported as Streamlit parity.

The current Streamlit UI also queries some SQLAlchemy rows directly for Automation status and calls a private inbox helper. That behavior is documented explicitly. Replace neither with an invented domain method; use the existing query/helper until a separately scoped service refactor is approved.
