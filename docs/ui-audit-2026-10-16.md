# FamilyFin UI audit - 16 October 2026

The current experience makes the user work through system state and financial terminology before answering a simple monthly question. The strongest improvement is a shorter overview followed by an actionable review queue, with statistics, rules and diagnostics available when needed.

## Scope and method

Used the connected Codex in-app browser and the Product Design audit workflow against the existing local app at http://127.0.0.1:3000. The app and API were already running on loopback; they were reused. The user signed in. No household transactions, classifications, accounts, budgets, preferences or automation runs were saved or changed. Temporary classification and budget drafts were discarded.

Inspected desktop at 1440×1000, mobile at 390×844, and dashboard/classification reflow at 320px. The separate anonymous sign-in capture uses the same app at localhost:3000, with a 1280×720 viewport and the default light theme. The authenticated session remained in its original dark theme.

All screenshots below were captured during this audit. Screenshots contain private development-copy data and are kept in the ignored frontend/test-results directory. No screenshots were uploaded to external design tools. A few full-page captures stitched incorrectly; they were rejected and are not evidence for this report.

## Redesign opportunities, in recommended order

1. **Put the monthly answer first.** A compact month selector, three clear income/expense/surplus figures, and one concise provisional-data notice should precede everything else. In this session the first financial value was at page y=754 on desktop and y=920 on mobile. Keep account coverage, transaction classification and period completeness distinct, but show their details in a focused review panel. Avoid describing operating surplus as spendable cash or an account balance.
2. **Turn classification into a task queue.** Show the transactions needing decisions immediately. Move coverage breakdowns, diagnostic codes and reusable-rule creation into secondary views. The current 320px all-history queue is about 18,000px tall with 50 cards before the rule editor. A compact table/list and one focused transaction editor would make review much easier. Retain imported-versus-corrected amount provenance and explicit correction confirmation.
3. **Make expense totals reconcile visibly.** Overview shows net consumption while expense behavior cards show gross consumption. Both can be correct, but refunds are not explained beside the expense summary, making the screens appear inconsistent. Show gross expenses, refunds and net expenses together. Where behavior is unknown, say it has not been classified rather than making zero fixed/variable spending look conclusive. Default the expense drill-down to expenses instead of income. Let category selection lead directly to its transactions.
4. **Use one useful setup state.** Net worth currently renders multiple empty sections for accounts, snapshots, trends and forecasts. Replace this with a short account → balance → review setup, revealing advanced sections as data becomes available. Planning should offer a clearly recommended start from existing transactions, alongside manual creation. Forecasts should link to their prerequisites. Mark the unfinished apartment tool as unavailable before users navigate into it.
5. **Replace diagnostics with next actions.** Data quality lists five different issue types under the same generic Hebrew “נדרשת בדיקת נתונים” wording. The classification summary still exposes raw English codes. Give each issue a distinct explanation, impact and action. Explain why “2 unclassified” and “10 require review” differ. Group repeated unavailable comparison messages rather than repeating them for every category.
6. **Reduce repeated text and competing scopes.** Multiple page titles, repeated definitions, warning pills and a privacy footer compete with the main task. Keep essential financial caveats visible, but move percentile definitions, rolling-window explanations, four-decimal statistics and technical details into optional analysis. Display normal money amounts consistently to two decimal places while preserving exact underlying values.
7. **Organize navigation around household tasks.** Keep an obvious route between overview, transactions, budget and net worth; group imports/classification as transaction-review tasks. Separate household insights from automation maintenance. Use consistent icon-library icons and clear labels, especially when desktop navigation collapses to icons. A review count near transactions would be more useful than an always-visible connection pill.

## Strengths worth preserving

- Reporting month and trend range remain independent, and the scoped classification link opens the expected month/currency/class filter.
- Missing October data is explained as unavailable rather than reported as zero.
- Contributor drill-down loads actual transactions; imported and effective transaction amounts are distinguished in the editor.
- Planning has explicit steps and a review before saving; source import separates preview from commit.
- Mobile More navigation opens, supports Escape, and exposes all secondary destinations. Dashboard document width stayed within 390px and 320px; wide analysis tables are contained in their own scrollers.
- Complete-only statistics correctly show an empty population when no complete months are available.

## Accessibility findings and limits

Confirmed from live DOM and interactions: planning validation does not mark its invalid input or move focus to it. Several supporting labels are only 10–12px, and long explanations make mobile reading harder. These are readability risks; font size alone is not a claim of a WCAG failure. Some dark-mode planning notices retain light fills, reducing consistency with surrounding panels. Full contrast, zoom, screen-reader and keyboard-only audits were not performed.

This was an audit of the existing Chromium-based in-app browser, not a Safari or physical-device certification. Saved budget, populated net-worth and saved forecast result screens could not be assessed with this household copy because those modules currently contain no records. No test records were added to fill those gaps. Imports, automation execution, classification saves, account closure, preference saves and financial writes were not performed during this audit. No new automated full-suite result is claimed.

## Recommended first implementation slice

Fix successful-revalidation draft loss and field-level validation first. Then redesign the overview and classification together: compact month controls, financial summary at the top, a short “what needs attention” panel, and a focused transaction editor. Follow with expense reconciliation and guided setup states. Larger visual alternatives should use the accepted screenshots as references and keep financial policy unchanged.
